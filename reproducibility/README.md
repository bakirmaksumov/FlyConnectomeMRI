# Reproducibility artifacts (Phases 8–10)

This folder holds the **exact** graph and data-split files used by the frozen FlyConnectomeMRI experiments. Each file was copied unchanged from the working directory: nothing was regenerated, and no experiment was re-run.

**Verification.** Every graph edge and node file, and every split manifest, matches byte for byte the SHA-256 recorded in the `metrics.json` of every run that used it. That covers all 155 runs: Phase 8 (30), Phase 9 (25) and Phase 10 (100). It also matches the checksums in [`docs/RESEARCH_PLAN.md`](../docs/RESEARCH_PLAN.md) and in [`docs/results/phase10_prerun/`](../docs/results/phase10_prerun/).

Check the files with `sha256sum -c SHA256SUMS.txt`, run from this folder.

**Not included:** MRI images, model checkpoints, and run logs or run folders.

## Contents

| Path | What it is | Used by |
|---|---|---|
| `graphs/eb128/drosophila_128_w20*` | EB-128 graph, edges with ≥ 20 synapses. This is the primary EB graph: 128 nodes, 3,047 edges | Phase 8 |
| `graphs/eb128/source_download/drosophila_128*` | Raw neuPrint download (all edges, weight ≥ 1) that the w20 graph was derived from | Source of the Phase 8 graph |
| `graphs/eb128/controls/{rewired,er,ws,ba}_128_w20_seed{0-4}*` | Control graphs matched to EB w20 | Phase 8 |
| `graphs/visual128/drosophila_visual_128_raw*` | Visual-system graph: local retinotopic columnar patch, 128 nodes, 989 edges, weight ≥ 1. Identical to the raw download `drosophila_visual_128.csv` (same SHA-256) | Phases 9–10 |
| `graphs/visual128/controls/{rewired,ws}_visual128_raw_seed{0-4}*` | Primary null (rewired) and WS control | Phases 9–10 |
| `graphs/visual128/controls/{er,ba}_visual128_raw_seed{0-4}*` | ER and BA controls | Phase 9 only |
| `node_order/*_node_order.csv` | Mapping `node_index → bodyId` (or control slot) actually used by the models: one file per graph, identical across all runs of that graph | Phases 8–10 |
| `splits/fixed_split/` | Slice manifest of the seed-0, 70/15/15 group-stratified split, plus metadata | Phases 8–9 |
| `splits/cv_leakage_safe/fold{1-5}/` | Per outer fold: slice manifest (train, val and test assignment), `exclusions.csv` (linked patient IDs removed from train/val, with reason `linked_to_test` or `linked_to_validation`) and metadata (per-fold `pos_weight` and normalisation statistics) | Phase 10 |
| `splits/cv_leakage_safe/{counts,exclusions_all,planned_runs}.csv`, `cv_prerun_report.json` | Fold counts before and after exclusions, all 76 exclusions, the 100 planned runs, and the leakage and OOF-coverage report | Phase 10 |
| `run_artifact_usage.csv` | One row per run (155): the graph and split files it used and their recorded SHA-256 | Phases 8–10 |
| `SHA256SUMS.txt` | Checksums of every file in this folder except this README and itself | — |

Each graph comes as three files: `<name>.csv` (`source,target,weight`, where source is presynaptic), `<name>_nodes.csv` (node table) and `<name>_metadata.json` (provenance, rule and statistics).

**Edge weights are not used by the models.** Only the presence and direction of an edge are used; there is one trainable weight per edge.

**Paths.** Paths inside the metadata files and `run_artifact_usage.csv` refer to the original layout (`data/connectome/…`, `data/splits/…`, `results/…`). The `results/` run folders are not published; the frozen summaries are in [`docs/results/`](../docs/results/).

## How to use these files

- **Graphs.** Copy the graph files to `data/connectome/` and run the configs in [`configs/`](../configs/). Training also needs the MRI images.
- **MRI data.** The images are **not** redistributed here. Download them from Figshare with `scripts/download_figshare.py` and prepare them with `scripts/prepare_dataset.py` and `scripts/prepare_cv_folds.py`. The manifests here record the SHA-256 of every source `.mat` slice, so the prepared data can be checked against them.

## Content notes

- **Patient identifiers.** The manifests contain the patient identifiers **as published by Figshare** (`cjdata.PID`, for example `100360` or `MR024780B`). They contain no names, dates or images. The `patient_link_key` column is this project's conservative grouping of possibly related identifiers. It is an assumption, not a known fact.
- **Slice fields.** Each manifest row has the source file name, the SHA-256 of the source `.mat` file, its image width and height, the class, the official `cv_fold` and the split assignment.
- **No secrets.** There are no absolute local paths, tokens or credentials in this folder. The neuPrint token was only ever read from an environment variable and is not stored anywhere.

## Missing or unconfirmed

- **Not recorded by the runs:** the SHA-256 of the graph `*_metadata.json` files, the per-fold `exclusions.csv` and `dataset_metadata.json`, and the fixed-split `dataset_metadata.json`. These are the files present in the working directory and should be the originals, but no run recorded their checksums. `exclusions_all.csv` is covered by the frozen checksums in `docs/results/phase10_prerun/`.
- **Code at download time.** The EB raw download records git commit `2c00739`, because the fetch was run before the fetch code was committed in `4863ba5`. See `docs/RESEARCH_PLAN.md`.
- **Not used and not included:** the unused weight variants (EB raw as a training graph, w5 and w10; visual w5). They were declared as sensitivity analyses only and were never trained on.
- **neuPrint terms.** neuPrint's own terms of service, as distinct from the MaleCNS licence, were **not checked**.
